# Deterministic Audit & Rejection Criteria (`flow-filetree-organizer` v1.2.0)

To prevent truncated outputs and empty approvals, every deliverable generated by `flow-filetree-organizer` MUST be checked against these falsifiable criteria using `[PASS]`, `[FAIL]`, or `[UNVERIFIED]`:

- `[PASS]`: Requirement verified against user input and output artifact.
- `[FAIL]`: Requirement violated with an explicit defect reason.
- `[UNVERIFIED]`: Cannot be verified due to missing input context.

---

### Rule 1: Verbatim Preservation of Original Prompt

- **Criterion**: Does the `Original request:` block contain the exact verbatim text submitted by the user without edits?
- **Test**: Compare the quoted `Original request:` string character-for-character against the raw user prompt.
- **Result**:
  - 100% verbatim copy preserved -> `[PASS]`
  - Paraphrased, summarized, or altered user prompt -> `[FAIL: Original request modified]`

---

### Rule 2: Strict MVP Scope Isolation (Anti-Bloat)

- **Criterion**: Does the core flow and file tree include only components essential to the user's primary idea?
- **Test**: Are unrequested enhancements, extra security layers, and secondary features cleanly isolated inside `### 5. Optional Suggestions (Outside MVP)`?
- **Result**:
  - Lean core MVP with extras isolated in Section 5 -> `[PASS]`
  - Core flow bloated with unrequested services without isolation -> `[FAIL: Unisolated MVP scope bloat]`

---

### Rule 3: Valid Parser-Safe Mermaid Syntax

- **Criterion**: Is the Mermaid diagram fenced in ` ```mermaid `, free of raw HTML tags, and using double-quoted node labels for any text containing special characters (`()`, `[]`, `/`, `:`)?
- **Test**: Validate `flowchart TD`/`LR` syntax and absence of broken brackets or unquoted parentheses.
- **Result**:
  - Clean, intuitive, parser-valid Mermaid diagram -> `[PASS]`
  - Broken Mermaid syntax, raw HTML tags, or unreadable labels -> `[FAIL: Invalid Mermaid syntax]`

---

### Rule 4: Commented ASCII Directory Tree

- **Criterion**: Does every folder and file node in the ASCII directory tree include an inline functional comment (`# <purpose>`)?
- **Test**: Inspect every entry inside the ` ```text ` file tree block for an explanatory comment.
- **Result**:
  - Every mapped folder and file declares its responsibility -> `[PASS]`
  - Entries left without purpose comments -> `[FAIL: File tree entries missing functional comments]`

---

### Rule 5: Explicit Export Option (`.md` / `.pdf`)

- **Criterion**: Does the response include `### 6. Export Option (.md / .pdf)` (or execute the export via `html-pdf-converter` when explicitly requested)?
- **Test**: Confirm that saving a single `.md` file or exporting `.pdf` via `html-pdf-converter` is offered or completed.
- **Result**:
  - Export option or generated `.md`/`.pdf` link present -> `[PASS]`
  - Export section omitted -> `[FAIL: Export option missing]`
